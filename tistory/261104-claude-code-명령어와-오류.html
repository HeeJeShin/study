Claude Code로 작업하다 보면 "Claude가 대신 실행해 주는 명령"과 "내가 직접 실행해야 하는 명령"이 나뉩니다. 오늘 GitHub 커밋 작성자를 바꾸는 작업을 하다가 둘의 경계에서 몇 번 헛돌았습니다. 같은 실수를 반복하지 않으려고 정리해 둡니다.

1. 내가 직접 명령을 실행하는 법: !

Claude Code 입력창에서 맨 앞 글자를 !로 쓰면, 그 줄은 Claude에게 보내는 메시지가 아니라 터미널 명령으로 실행됩니다. 실행 결과도 대화에 남기 때문에 Claude가 이어서 확인할 수 있습니다.

❌  " !cd ~/study && git push"        ← 맨 앞에 공백 → 그냥 메시지로 전송됨
❌  "!cd ~/study && git commit         ← 줄바꿈 → 명령이 끊기거나 메시지로 전송됨
       --amend"
✅  "!cd ~/study && git commit --amend --no-edit --reset-author && git push --force-with-lease"

정리하면 세 가지만 지키면 됩니다.

  1. !는 입력창의 첫 글자여야 합니다. 붙여넣을 때 앞에 공백이 딸려 들어오면, !만 직접 타이핑하고 그 뒤에 붙여넣습니다.
  2. 명령은 한 줄로 씁니다. 여러 명령은 &&로 잇습니다. 앞 명령이 성공해야 다음 명령이 실행됩니다.
  3. gh auth login처럼 내가 직접 입력해야 하는 명령도 이 방식으로 실행합니다.

저는 앞에 공백이 들어간 채로, 그리고 여러 줄로 붙여넣은 채로 세 번을 보냈는데, 세 번 모두 명령이 실행되지 않고 메시지로만 전달됐습니다.

2. 자주 만나는 오류 6가지

메시지 뜻 할 일
Permission denied … [Git Destructive] force push처럼 기록을 덮어쓰는 명령이라 Claude가 대신 못 하게 막음 정말 덮어써도 되는지 확인한 뒤 내가 !로 직접 실행
classifier gave no verdict (error) 자동 승인 검사가 일시적으로 응답하지 않음. 명령이 위험해서가 아님 잠시 후 다시 시도. 계속 안 되면 파일 편집 도구 같은 다른 방법으로
Blocked: sleep … followed by … 긴 sleep으로 시간을 때우며 기다리는 것을 막음 until <조건>; do sleep 2; done처럼 조건을 확인하며 기다리기
Cannot find module '…/scratchpad/…' 임시 폴더(scratchpad)가 비워져 스크립트가 사라짐 자주 쓰는 스크립트는 저장소 안(scripts/)에 두기
Cannot find module 'puppeteer' 스크립트가 있는 위치에서 라이브러리를 찾지 못함 라이브러리가 설치된 프로젝트에서 실행하거나 NODE_PATH 지정
Shell cwd was reset to … 명령이 끝나면 작업 폴더가 원래대로 돌아감. 오류가 아님 매번 cd 경로 &&로 시작하거나 절대 경로 쓰기

가장 중요한 건 첫 번째와 두 번째를 구분하는 것입니다.

  • [Git Destructive]는 "위험하니까 사람이 판단하라"는 뜻입니다. 같은 일을 다른 명령으로 돌려서 시키면 안 되고, 내가 확인한 뒤 직접 실행해야 합니다.
  • no verdict는 검사 서버가 잠깐 응답하지 않은 것입니다. 명령 자체는 문제가 없으니 다시 시도하면 됩니다.

3. 실제로 겪은 일: 커밋 작성자 바꾸기

스터디 저장소의 첫 커밋이 예전 회사 메일로 올라가 있었습니다. 앞으로를 위해 개인 메일로 바꾸려고 했습니다.

  1. git config --global user.email <개인 메일>로 앞으로의 커밋 이메일을 바꿨습니다. 이미 만든 커밋은 이걸로 바뀌지 않습니다.
  2. 방금 만든 커밋은 git commit --amend --no-edit --reset-author로 작성자를 바꿨습니다. 이러면 커밋 ID가 새로 생깁니다.
  3. 원격에 다시 올리려면 기록을 덮어써야 해서 git push --force-with-lease가 필요했습니다. 이 단계에서 Claude 쪽은 [Git Destructive]로 막혔고, 제가 !로 직접 실행해 해결했습니다.

--force-with-lease는 --force보다 안전합니다. 원격이 내가 마지막으로 본 상태와 다르면(그사이 누가 푸시했으면) 덮어쓰지 않고 멈추기 때문입니다.

하나 더 배운 점이 있습니다. GitHub 잔디는 커밋에 적힌 이메일이 내 계정(Settings → Emails)에 등록돼 있어야 잡힙니다. 개인 메일을 계정에 등록하기 전에는 커밋이 계정에 연결되지 않았고, 등록한 뒤에야 연결됐습니다. 예전 회사 메일로 한 커밋들도 그 메일을 계정에서 지우면 잔디에서 사라지니 남겨 둬야 합니다.

# 커밋이 내 계정에 연결됐는지 확인 (null이면 연결 안 됨)
gh api repos/<계정>/<저장소>/commits/main --jq .author.login

4. 정리

  • 내가 실행할 명령은 맨 앞 ! + 한 줄로 씁니다.
  • 막힌 것(위험해서)과 응답 없음(일시적)을 구분합니다. 막힌 작업은 우회하지 않고 내가 판단해서 실행합니다.
  • 자주 쓰는 스크립트는 임시 폴더가 아니라 저장소 안에 둡니다.

AI 코딩 도구가 위험한 작업을 스스로 막아 두는 건 오히려 안심되는 부분이었습니다. 빠르게 맡기되, 기록을 지우거나 덮어쓰는 결정은 사람이 하는 방식이 맞다고 생각합니다.
